언리얼의 핵심 구조

 1. 상속
 2. 컴포넌트 패턴

-------------------------------------------------

상속

UClass
 : UObject를 상속받아 만들어진 클래스. Unreal의 고유 클래스들은 Uobject를 상속 받아서 만들어진다.

 1. 메모리
	- UObject 기반 클래스는 GC(Garbage Collection)에 의해 관리
	- 메모리 할당 및 해제가 자동으로 이루어짐
	- UPROPERTY() 선언하면 GC가 관리

 2. 리플렉션 (Reflection)
	- 클래스, 변수, 함수 등의 메타데이터 추적, 동적으로 다룰 수 있게 해줌
	- 클래스 : UCLASS()
	- 멤버 변수 : UPROPERTY()
	- 함수 : UFUNCTION()
	=> 코드에서 정의한 클래스나 함수를 블루프린트에서 사용
	=> 에디터에서 객체 동적 수정

-------------------------------------------------

객체
 
 1. UMyAnim : U... UObject
	- 일반적으로 씬에 배치될 수 없음

 2. AMyActor : A... Actor
	- 씬에 배치될 수 있음
	- 액터 : mesh, material, transform
	- 폰 : input controller, movement 추가
	- 캐릭터 : skeletal mesh, capsule, anim 추가

 참고 : 클래스는 객체가 아님.

-------------------------------------------------

컴포넌트
 : 객체나 씬의 기능을 나누고 조립할 수 있도록 하는 개별적인 부품

1. Actor Component
	- 동작 담당
	- 이동, 점프, 체력 등
	- 공간적 요소는 없음

2. Scene Component
	- 공간적인 개념
	- 어디에 배치되는지 결정
	- 눈에 보이는 무언가 (카메라, 광원, 모델)
	- 다른 컴포넌트에 붙을 수 있음 (부모가 움직이면 자식도 움직임)

C 언어의 printf()
 : 다양한 데이터 타입을 문자열로 변환하여 출력
	- 데이터 타입마다 변환 방식이 다름
	=> 형식 지정자(%d, %f, %s 등)를 사용

TEXT()
 : 언리얼 엔진에서 문자열을 안전하게 사용하기 위한 장치
	- C++에서는 기본적으로 문자열이 ANSI(1바이트)로 저장
	- 언리얼은 유니코드(2바이트)로 저장
	=> TEXT()를 이용해 문자열을 유니코드로 처리

Delegate

 0. Delegate, 콜백 함수
	- Delegate : 함수 포인터의 객체지향적인 형태. 이벤트 시스템 구축에 사용
	- 콜백함수와 유사하게 동작
		- 콜백 함수 : 함수 인자로 전달되어 특정 시점에서 실행되는 함수. 함수 포인터 이용
	- 사용 이유
		- 콜백함수와는 다르게 여러 함수 포인터를 관리할 필요가 없음 (멀티캐스트)
			- 콜백 함수의 경우 리스트나 벡터로 관리해야 함
		- 메모리 관리, 동적 바인딩 (다이나믹)

 1. 싱글캐스트 Delegate
	- 하나의 함수만 바인딩 가능
	- 한 번에 하나의 이벤트 처리할 때 사용
	- BindAction() -> Execute()

 2. 멀티캐스트 Delegate
	- 여러 개의 함수를 동시에 바인딩
	- 이벤트 시스템 구축
	- 반환값을 받을 수 없음 (여러 함수 중 어떤 값을 반환할지 모호함)
	- AddAction() -> BroadCast()

 3. Dynamic Delegate
	- 블루프린트에서 바인딩 가능
	- UFUNCTION(), AddDynamic() 사용
	- 런타임 중에도 안전하게 관리 가능 (GC 지원)
	- AddDynamic() -> Broadcast()

AIController

 1. Pawn
	- 캐릭터 / AI가 조종하는 객체
 2. AIController
	- AI가 캐릭터를 조종하는 컨트롤러
	- Pawn을 조종하고 BT 실행
 3. BehaviorTree (BT)
	- AI의 행동 결정
	- 태스크(Task), 데코레이터(Decorator), 서비스(Service) 노드가 실행됨
 4. BlackBoard (BB)
	- BT가 공유하는 데이터 저장소
	- 행동을 결정할 때 참고하는 일종의 메모장

 => Pawn -> AIController -> BT, BB
-------------------------------------------------

Behavior Tree

 - Composite Node
 1. Sequence
 	- 자식 노드를 순차적으로 실행. 하나라도 실패하면 즉시 실패
 2. Selector
 	- 순차 실행, 하나라도 성공하면 즉시 성공
 3. Decorator
 	- 자식 노드에 조건을 추가하거나 변경
 	- 자식 노드 실행 전에 조건 확인
 4. Service
 	- 주기적으로 실행되며 AI 상태를 지속적으로 확인, 업데이트
 	- 주변 적 감지, HP 확인 등
 5. Task
 	- 실제 행동 수행 노드
 	- 단 하나의 행동. 성공 혹은 실패 반환
